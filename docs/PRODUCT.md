# 叙事：从事件到章节的小说创作工作室

## 产品判断

不是先造一个能写几段话的聊天窗口，而是让作者掌握一条可以追溯的创作链：事件素材 → 章节目标 → 人物选择 → 正文 → 审阅 AI 建议。AI 内容先展示、后插入，作者始终决定故事如何发生。

以下是基于已有产品认知的方向比较，不是实时市场调研：本次外部竞品网站访问受到环境网络策略限制，未核实最新功能、价格、服务条款或可用地域。

| 参考产品 | 可借鉴方向 | 本系统选择 |
| --- | --- | --- |
| Scrivener | 长篇分章、研究素材、组织文稿 | 章节与素材并置，缩短切换路径 |
| Sudowrite | 续写、描写、脑暴等写作辅助 | 用场景、动作、对白、神态分类，先审阅再采用 |
| Novelcrafter | 世界设定、人物资料与模型上下文 | 将角色和当前章节事件纳入生成请求 |
| 国内常见网文写作工具 | 字数、章节管理、基础写作体验 | 中文优先、个人部署、通义千问优先 |

## 第一版已实现

- 现有「作品」模块内提供多作品书架：新建、搜索、排序、编辑信息、移入回收站及恢复；各作品独立保存正文、角色和事件。
- 每部作品支持多章节写作，章节标题、梗概、正文编辑，新建/删除章节。
- 服务端 SQLite 自动保存；版本冲突时停止覆盖并提示导出当前内容。
- 事件素材支持手动创建、搜索、删除、JSON/TXT/Markdown 导入；事件可以关联到章节。
- 来源信息随事件保留，支持原创/合法授权素材；不提供未经授权抓取小说功能。
- 角色设定编辑，生成时纳入上下文。
- 六类 AI 辅助，默认百炼兼容接口 qwen-plus，可配置其他兼容服务。无密钥时明确标示预置示例。
- 专注模式、字号切换、字体切换、正文 TXT/Markdown 导出、完整 JSON 备份。
- 私人工作室密码登录、Docker 单容器部署与持久卷。

## 可以一起优化的想象

1. **事件编织台**：把素材分成“目标—阻碍—选择—代价—新局面”。同一个事件可以被改写成悬疑、言情、仙侠三种版本；记录来源与改写链，避免直接搬运文本。
2. **因果时间线**：拖动事件卡，自动提示前置条件、人物是否具备信息、时间/地点是否冲突。先做可解释的规则检查，再让模型补充建议。
3. **人物秘密账本**：分别记录“真实发生”“人物相信”“读者知道”。生成对白时限定角色知识，减少穿帮。
4. **伏笔回收地图**：埋下、呼应、误导、回收四种状态；每条伏笔连接具体章节与段落，不只放在聊天历史。
5. **导演模式**：选择一段正文，从空间、镜头、动作、潜台词四个角度生成备选，支持逐句对照和撤销。
6. **声音卡**：为角色制定词汇、句长、禁用表达和说话动机，检测角色“都像同一个人”的问题。
7. **分支沙盒**：从某章复制出平行版本，试写三种结局；正式稿与实验稿独立，作者可以合并选择。
8. **素材市场/团队协作**：在有确切需求后加入账户、授权协议、权限和审核，不把个人工作室直接公开为多租户平台。

## 边界与下一轮优先级

当前面向单人、单工作室，支持多作品切换；尚不支持多账户、多人实时协作、完整版本历史或富文本排版。字数按去除空白后的字符计数，目标是作品目标，不伪装成每日写作统计。预置示例不会随提示实时生成。

建议下一轮先验证实际作者工作流：导入 20 个已授权事件，编排 5 章，完成一章正文；再决定优先做因果时间线、伏笔管理还是版本回滚。
